# 1.18.0 – OpenAPI 3.1 tanımı; llms-full.txt değerlendirmesi (plan, onaylandı)

Kaynak: `docs/planlar/GELISTIRME-ALANLARI.md` ("OpenAPI 3.1 + llms-full.txt"), 2026-10-01.

## A. OpenAPI 3.1 belgesi (yapılacak)

### Neden
- Fonksiyon çağırabilen agentlar ve araçlar (ör. ChatGPT'nin özel GPT "Actions" özelliği, OpenAPI'den araç üreten
  kütüphaneler) bir API'yi **OpenAPI** belgesinden tanır. Bugün bizde yalnızca kaynak başına JSON şemaları var
  (`/aihs/v1/schema/…`); uç noktaları, parametreleri ve yanıtları tek yerde anlatan belge yok.
- Keşif bağlantımız (1.7.0) `rel="service-desc"` ile REST kök adresini gösteriyor. RFC 8631'e göre `service-desc`
  makinece okunur bir **hizmet tanımı** göstermeli; WordPress'in ad alanı listesi bunu tam karşılamıyor. OpenAPI
  belgesi tam da budur.

### Ne yapılacak
1. `GET /wp-json/aihs/v1/openapi.json` – **OpenAPI 3.1.0** belgesi, sitedeki açık duruma göre üretilir:
   - `info` (firma adı, eklenti sürümü), `servers` (sitenin REST kökü).
   - Yollar: `/profile`, `/listings` (parametreler: `type`, `category`, `region`, `page`, `per_page` – kayıtlı rota
     tanımlarından), `/listings/{id}`, `/templates`; portal açıksa `/businesses`; teklif kutusu açıksa
     `POST /inquiries` (istek gövdesi şeması, 400/429).
   - Yanıt şemaları mevcut `RestSchemas`'tan (`components/schemas`); OpenAPI 3.1 JSON Schema 2020-12 ile uyumlu
     olduğu için ayrı şema yazılmaz, tek kaynak korunur.
   - Ortak yanıtlar: 429 + `Retry-After` başlığı, 404; önbellek başlıkları açıklamada.
   - Yalnızca okuma; kimlik doğrulama yok (`security: []`).
2. **Keşif:** `rel="service-desc"` artık bu belgeyi gösterir, tür `application/vnd.oai.openapi+json` (IANA'da
   OpenAPI için kayıtlı ortam türü). llms.txt'de "AI agentlar için" / API satırına OpenAPI bağlantısı.
3. Anahtar: REST API'nin (`rest_api`) parçası; ayrı anahtar yok (onaylı istisna önerisi – mevcut `/schema/*` uç noktaları
   gibi, zaten herkese açık olan API'yi tarif eder, yeni veri açmaz). REST kapalıysa belge de yok.

### Doğrulama (kanıtlanmış yöntem)
- Belge, OpenAPI Initiative'in yayınladığı **resmi OpenAPI 3.1 JSON Şeması**na (spec.openapis.org, 2022-10-07) karşı
  testte doğrulanır. Bunun için yalnızca geliştirmede kullanılan bir JSON Schema doğrulayıcı eklenir:
  `opis/json-schema` (JSON Schema 2020-12 destekli, yaygın PHP kütüphanesi; eklenti paketine girmez). Resmi şema dosyası
  `tests/Fixtures/` altına kaynağıyla birlikte konur.
- **Sapma testi:** `aihs/v1` altında kayıtlı her rota belgede var; belgede olup kayıtlı olmayan yol yok. İleride yeni
  uç nokta eklenip belge unutulursa test kalır.

## B. llms-full.txt (değerlendirme ve öneri)

### Bulgu
- `llms-full.txt` **llms.txt önerisinin (llmstxt.org) parçası değil**; belge sitelerinin (Mintlify vb.) yaygınlaştırdığı
  bir teamül. Öneri ise sayfaların Markdown sürümlerini `rel="alternate" type="text/markdown"` ile bağlamayı öneriyor.
- Bizim llms.txt'miz zaten **her geçerli ilanı tüm ayrıntısıyla** (açıklama, fiyat, miktar, teslim, şablon alanları)
  içeriyor. Bugün bir llms-full.txt aynı metni tekrar ederdi; ek değeri yok.

### Öneri
1. **Şimdi (küçük, standarda uygun):** /ai-katalog/ sayfasına `<link rel="alternate" type="text/markdown"
   href="/llms.txt">` – önerinin tavsiye ettiği yolla, katalogun Markdown sürümünün nerede olduğunu bildirir.
2. **Geliştirme alanına:** katalog büyüdüğünde (ör. 50+ ilan) llms.txt'yi özet hâline getirip tam listeyi
   `/llms-full.txt`'ye taşımak. Pilot katalogları küçük olduğu için bugün gerekmiyor; `GELISTIRME-ALANLARI.md`'ye yazılır.
